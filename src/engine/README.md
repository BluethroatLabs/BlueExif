# BlueExif engine

Pure TypeScript, dependency-light metadata engine. Runs in browsers (main
thread or workers) and in Node (tests). No DOM APIs (`DOMParser` etc.) — use
`core/xml.ts`.

## Layout

```
core/types.ts    contracts: FormatHandler, Metadata, Field, Edits, Source …
core/binary.ts   Reader/Writer, text codecs, crc32, base64, concat, toBlob
core/fields.ts   field builders, value coercion (asText/asList/asGps…),
                 dates (parseDate/toIso/toExifDate), GPS, image sniffing
core/xml.ts      small namespace-aware XML DOM + serializer
core/zip.ts      ZIP reader + surgical rewriter (unchanged entries copied raw)
core/icc.ts      ICC profile description
exif/            TIFF/EXIF parse+write, tag dictionary, EXIF <-> fields
xmp/xmp.ts       XMP packet model, XMP <-> fields
iptc/iptc.ts     IPTC-IIM + Photoshop IRB
formats/*.ts     one handler per container format (jpeg.ts is the reference)
formats/index.ts handler registry
test/helpers.ts  fixtures, edits() builder, ExifTool (WASM) oracle
```

## Handler contract (see `core/types.ts`)

- `detect(ctx)` → 0 (no), 1 (extension only), 2 (magic), 3 (magic + structure).
- `read(src)` → `Metadata` with `groups` of `fields`. Technical facts that
  cannot be edited (dimensions, duration, codec, bitrate, page count) go in
  `info`, not in fields.
- `write(src, edits)` re-parses `src`, applies `edits` (by field id) and returns
  a new `Blob`. Unknown ids are ignored. Setting an id that is not present but
  appears in some group's `addable` list must create that field.
- `strip(src, opts)` removes every piece of metadata that is not needed to
  decode/render/play the file. Honour `keepOrientation`, `keepColorProfile`,
  `keepCoverArt` where they apply. Strip must also remove things the reader
  only shows as raw fields (unknown chunks, maker notes, trailing data…).
- Throw `MetadataError` with a user-friendly message for unsupported variants or
  invalid values. Push non-fatal issues to `Metadata.warnings`.

## Field conventions

- Field ids are `<source>:<key>`, deterministic for the same bytes, e.g.
  `exif:ifd0:013b`, `xmp:<nsURI>|<name>`, `iptc:2:25`, `id3:TIT2`,
  `vorbis:ARTIST`, `mp4:©nam`, `pdf:Author`, `docx:core:dc:creator`.
- Group-wide container removal uses `groupKey(group.id)` and requires
  `group.removable = true`. The UI otherwise removes groups field by field.
- Every field that reveals something about a person, place, device, time or
  software gets a `sensitivity` — it drives the privacy summary.
- `raw` fields are read-only but normally `removable: true`; give them a
  helpful `display` string (sizes via `formatBytes`).
- Values: text/multiline/datetime/enum → string; integer/number → number;
  list → string[]; gps → `GpsValue`; image → `ImageValue`. Datetimes are
  ISO-like strings (`toIso(parseDate(x))`), shown with `displayDate`.
- Cover art / embedded pictures are `image` fields; adding a picture uses an
  `addable` spec of kind `image` (UI supplies `{ mime, data }`).

## Large files

`Source.bytes()` loads everything; fine for images and documents. For audio
and video prefer `src.read(offset, len)` for headers and carry payloads over
with `src.slice(start, end)` inside the output `toBlob([...])` — zero-copy.

## Tests

- Fixtures live in `fixtures/<area>/` and are generated by
  `scripts/fixtures/<area>.mjs` (`node scripts/make-fixtures.mjs <area>`) using
  ffmpeg, macOS tools (`sips`, `textutil`, `afconvert`) and ExifTool WASM for
  rich metadata. Keep fixtures tiny (a few KB).
- Every writer is verified with the ExifTool oracle: `exiftool(bytes, name)`
  returns `{ 'Group:Tag': value }`; `etProblems(tags)` must be `[]`.
- Test: read values, edit (set/add/remove) and re-read with both our reader and
  ExifTool, strip and confirm nothing identifying remains while the payload is
  intact (ffprobe/ffmpeg decode for media).
